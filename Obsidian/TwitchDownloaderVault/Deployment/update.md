# update.sh

Parent: [[Index]]

## Назначение

`update.sh` в корне репозитория обновляет серверное развёртывание TwitchDownloader одной
командой `./update.sh`: подтягивает `master` и пересобирает и перезапускает Compose-сервис
`docker/docker-compose.yml`. Каталог проекта определяется по расположению скрипта
(симлинк разрешается), поэтому путь развёртывания не зашит.

## Файлы

- `update.sh` — Bash-скрипт обновления.
- `docker/docker-compose.yml` — Compose-сервис, которым управляет скрипт.
- `docker/.env` — обязательная локальная конфигурация, не коммитится.
- `docker/README.md` — пользовательская инструкция.

## Поток выполнения

1. Проверяются `git`, `docker`, Git-репозиторий, Compose-файл и `docker/.env`.
2. Проверяется текущая ветка `master`, remote `origin` и отсутствие локальных изменений.
3. Выполняется `git pull --ff-only origin master`.
4. Образ собирается `docker compose ... build --pull`, пока работает прежний контейнер.
   Ошибка сборки завершает скрипт, прежний контейнер продолжает работать.
5. Контейнер пересоздаётся `up -d --force-recreate --remove-orphans` и выводится `ps`.

## Важные детали

- Данные контейнера — bind-mount каталоги `docker/data/` (настройки, `history.db`) и
  `docker/downloads/` (записи), а также `docker/.env` — игнорируются Git, не мешают
  проверке чистоты репозитория и не удаляются: скрипт не вызывает `down` и не трогает volumes.
- Пересоздание контейнера останавливает его через `SIGINT`; активные `.recording`
  закрываются и финализируются восстановлением при старте нового контейнера (см. [[api/docker]]).
- Весь код находится в функции `main`, которая вызывается последней строкой: bash разбирает
  функцию целиком, поэтому `git pull`, меняющий сам `update.sh`, не ломает текущий запуск.
- Незакоммиченные изменения блокируют обновление, поэтому локальные правки не
  перезаписываются во время деплоя.
