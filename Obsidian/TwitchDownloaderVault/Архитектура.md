## Tech Stack

| Слой | Технология | Где используется |
|------|------------|------------------|
| Язык | C# с nullable reference types и implicit usings | Оба CLI-проекта |
| Runtime v1 | .NET 8, `net8.0-windows10.0.26100.0`, x64 | `TwitchDownloader.CLI` |
| Runtime v2 | .NET 10, `net10.0` | `TwitchDownloader2.CLI` |
| Telegram | `Telegram.Bot` 22.0.2 / 22.7.4 | v1 / v2 |
| Конфигурация v2 | `System.Text.Json` → UTF-8 → Base64 | `Data/settings.data` |
| Загрузка | `yt-dlp` для live/HLS + `ffmpeg` для потоков | v1, v2 и Docker |
| Контейнеризация | Docker multi-stage, Compose | `docker/` |
| Обновление | Bash, `git pull --ff-only`, Docker Compose | `scripts/updatetwitch` |

## Компоненты и ответственность

| Компонент | Роль |
|-----------|------|
| `TwitchDownloader.CLI` | Legacy Windows-контур: файлы `token`/`id`, права администратора, inline-клавиатуры и отдельные ffmpeg-процессы |
| `Program` v2 | Загружает настройки, создаёт Telegram/checker/downloader и обрабатывает остановку процесса |
| `AppSettings` | Загружает Base64 JSON, применяет env-переменные и сохраняет каналы/путь без env-секретов |
| `TelegramService` | Приём апдейтов только от владельца, reply-клавиатуры, команды и многошаговый ввод |
| `TwitchCheckerService` | Фоновый цикл с интервалом 1 минута, `yt-dlp`-проверка live и защита от повторного запуска |
| `TwitchDownloaderService` | Четыре параллельных ffmpeg-процесса, остановка сессии, таймаут завершения и SHA256-дедупликация |
| `Keyboards` | Фабрика клавиатур Telegram |
| `docker/` | Образ и Compose-манифест с env и постоянными volumes |
| `scripts/updatetwitch` | Серверное обновление с проверками и попыткой восстановить прежний контейнер |

## Точки входа и запуск

### v1

`TwitchDownloader.CLI/Program.cs` проверяет права администратора, выбирает путь
загрузки из первого аргумента, создаёт `DownloadService`, `TelegramService` и
`ConverterService`, затем читает файлы `token` и `id`. Бот запускается через
`StartBotAsync`, а главный поток остаётся в `Thread.Sleep(Timeout.Infinite)`.

### v2

`TwitchDownloader2.CLI/Program.cs` сначала загружает `AppSettings`, проверяет
обязательные Telegram-настройки, запускает `TelegramService`,
`TwitchDownloaderService` и `TwitchCheckerService`, затем ждёт `STOP`, `Ctrl+C`
или сигнал завершения. При остановке настройки сохраняются, Telegram отменяется,
checker освобождает свой worker thread и события.

В Docker stdin перенаправлен, поэтому v2 ждёт сигнал процесса и не требует TTY.

## Сквозные потоки

### Конфигурация v2

1. `AppSettings.Load()` читает `Data/settings.data`, если файл существует.
2. `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID` и `DOWNLOAD_PATH` имеют приоритет.
3. В интерактивном запуске недостающие Telegram-поля запрашиваются в консоли;
   headless-запуск завершается с понятной ошибкой.
4. `Save()` сохраняет каналы и путь в Base64 JSON, но не дублирует секреты,
   заданные через environment.

### Автоматическая загрузка Twitch

```text
TrackedChannels
  -> TwitchCheckerService.WorkerLoop (раз в минуту)
  -> yt-dlp --print title (exit code 0 = live)
  -> TryMarkDownloadStarted
  -> TwitchDownloaderService.StartDownload
  -> yt-dlp --get-url
  -> 2 video + 2 audio ffmpeg processes
  -> wait first exit + 10s grace period
  -> SHA256 comparison and duplicate cleanup
  -> Telegram notification + MarkDownloadFinished
```

Если один процесс зависает после первого завершения, остальные принудительно
завершаются. При аварийном исходе checker получает `ForceCheck()`; при ручной
остановке пользователя повторный запуск не инициируется.

### Telegram

Доступ проверяется по `_ownerId`. Кнопки меняют локальные bool-триггеры
`TelegramService`: добавление/удаление канала, изменение пути и ручная остановка
сессии. Сервис сохраняет настройки после изменений и может вызвать
`TwitchChecker.ForceCheck()` для немедленной проверки.

### Серверное обновление

`scripts/updatetwitch` проверяет наличие `git`, Docker, репозитория, Compose-файла
и `docker/.env`, убеждается в ветке `master` и чистом рабочем дереве, выполняет
`git pull --ff-only`, останавливает контейнер, собирает образ с `--pull` и
запускает Compose с `--force-recreate --remove-orphans`. `trap` пытается запустить
прежний контейнер, если сборка или запуск завершились ошибкой; volumes не удаляются.

## Базовые паттерны и ограничения

- Сервисы v2 связаны через статические свойства `Program`, а не через DI.
- Состояние загрузок защищается `ConcurrentDictionary`, `lock` и флагом
  `volatile ForcedByUser`; checker использует отдельный background `Thread`.
- Внешние CLI запускаются через `System.Diagnostics.Process`; v2 использует
  `ArgumentList`, `CreateNoWindow` и `-nostdin`, что нужно для Docker.
- Две одинаковые записи сохраняются намеренно: после загрузки сравниваются по
  SHA256, и дубликат удаляется.
- Base64 в `settings.data` — обфускация, а не шифрование. Секреты для Docker
  передаются через `.env` и не должны коммититься.

## Как добавить новый компонент

1. Добавь исходный файл в фактический проект/домен и подключи его к потоку через
   существующую точку входа.
2. Создай атомарную заметку `{Domain}/{Component}.md` с файлами, ключевыми
   методами и зависимостями; добавь её в [[Index]].
3. Если меняется взаимодействие компонентов, обнови этот файл и соответствующие
   wikilinks.
4. При изменении метода используй краткий формат
   `methodName(param: Type): ReturnType — назначение`; удалённый метод помечай
   зачёркиванием с датой.
5. Новые changelog-файлы не создавай: изменения фиксируются в git.
