# Архитектура

## Tech Stack

| Слой | Технология | Где используется |
|------|------------|------------------|
| Язык | C# с nullable reference types и implicit usings | Оба CLI-проекта |
| Runtime v1 / v2 | .NET 8 Windows / .NET 10 cross-platform | `TwitchDownloader.CLI` / `TwitchDownloader2.CLI` |
| Telegram | Telegram.Bot 22.0.2 / 22.7.4 | v1 / v2 |
| Конфигурация v2 | `System.Text.Json` → UTF-8 → Base64 | `Data/settings.data` |
| Twitch live v2 | Публичные GraphQL playback token + Usher HLS | [[modules/v2-twitch-playback]] |
| Media v2 | `ffmpeg` + `ffprobe` | Финализация, проверка и recovery |
| Контейнеризация | Docker multi-stage + Compose | `docker/` |

`yt-dlp` используется только legacy v1. Docker runtime v2 его не содержит.

## Компоненты v2

| Компонент | Роль |
|-----------|------|
| `Program` | Собирает зависимости, запускает background recovery/checker/Telegram и координирует быстрый shutdown |
| `AppSettings` | Хранит tracked-каналы, путь и persisted pause-until-offline; env-секреты не пишет на диск |
| `TelegramService` | Команды владельца, session-ID callbacks и уведомления о завершении эфира и обработки |
| `TwitchCheckerService` | Только расписание: раз в минуту вызывает downloader для tracked-каналов |
| `TwitchDownloaderService` | Единственный владелец recording-сессий, резерва канала и переходов Recording → Finalizing |
| `TwitchPlaybackClient` / `HlsPlaylistParser` | GraphQL/Usher, source/fallback, media playlist и сегменты |
| `LiveStreamRecorder` | Последовательно пишет один HLS-поток, дедуплицирует sequence, считает рекламу/дыры |
| `MediaFinalizer` | Создаёт, проверяет и атомарно публикует MP4; восстанавливает orphan `.recording` |
| `ProcessMediaToolRunner` | Отменяемый запуск `ffmpeg`/`ffprobe` без shell |
| `Keyboards` | Reply/inline клавиатуры и codec stop callback |
| `TwitchDownloader2.CLI.Tests` | xUnit-контур с подставными HTTP/process/delay-адаптерами |

## Сквозной live-поток

```text
TrackedChannels
  -> TwitchCheckerService (timer / ForceCheck)
  -> TwitchDownloaderService.TryStartDownloadAsync
  -> Twitch GraphQL playback token
  -> Twitch Usher master playlist -> source (или fallback)
  -> один LiveStreamRecorder на канал
       media playlist -> EXT-X-MEDIA-SEQUENCE dedupe
       EXTINF ad filter (fail-open) -> TS или EXT-X-MAP + CMAF
  -> live_<channel>_<timestamp>_source_<sessionId>.recording
  -> естественный конец: Telegram «трансляция завершена» + освобождение резерва канала
  -> MediaFinalizer -> .mp4.part (параллельно может стартовать новая запись канала)
  -> ffprobe: expected duration, A/V drift, Non-monotonous DTS
  -> atomic rename .mp4 + Telegram «обработка завершена»
```

Разные каналы независимы. Две попытки старта одного канала сходятся в одном lock и
получают `Started` + `AlreadyActive`; отдельного checker-флага нет.

## Пользовательская отмена

```text
Telegram inline callback stop_download:<sessionId>
  -> RequestStopAsync
  -> persist channel in PausedUntilOfflineChannels
  -> cancel recorder HTTP
  -> state Finalizing (persisted pause keeps the channel reservation until finalization)
  -> partial MP4 validation
  -> final metrics notification
```

Пока Twitch подтверждает live, любой плановый или forced check возвращает `Suppressed`.
Сетевая ошибка паузу сохраняет. Только явный `Offline` удаляет её. UUID не даёт старой
Telegram-кнопке остановить replacement-сессию.

## Shutdown и recovery

При `SIGINT`/`Ctrl+C` `Program` за общий 10-секундный budget останавливает checker,
отменяет recovery, HTTP и media tools, закрывает file streams и не начинает финализацию
active-сессий. Compose оставляет процессу 30 секунд.

Следующий запуск до плановых записей перечисляет только `*.recording`. Контейнер
определяется по первым байтам, реальная длительность — декодирующим проходом ffmpeg,
после чего применяется обычная финализация. Старые `*_video_*.ts`/`*_audio_*.aac`
не входят в выборку.

## Инварианты сохранности

- `.mp4` появляется только после успешной проверки `.mp4.part`.
- При естественном конце `RecordingEndedAsync` отправляется до результата финализации, а
  `RecordingCompletedAsync` — после проверки и публикации MP4.
- Сессия в `Finalizing` остаётся в `_sessionsById` для статуса и адресной кнопки. После естественного
  конца она удаляется из `_sessionsByChannel` до завершения MP4, поэтому канал может записываться
  снова; после ручной отмены или ошибки резерв сохраняется до очистки worker-а.
- Допуск expected/video и audio/video — 2 секунды; `Non-monotonous DTS` запрещён.
- При ошибке остаются `.recording.failed` и доступный `.mp4.failed`.
- Docker shutdown предпочитает быстро сохранить сырьё; ручная отмена предпочитает сразу
  собрать частичный MP4.
- Base64 settings — обфускация, не шифрование.
- Запись `settings.data` и мутации tracked/pause-коллекций сериализованы одним lock.

## Legacy v1

`TwitchDownloader.CLI` остаётся Windows/.NET 8 контуром с `yt-dlp`, отдельными
video/audio ffmpeg-процессами и последующим merge. Новая архитектура его не затрагивает.
